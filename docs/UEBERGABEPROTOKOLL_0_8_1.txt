Verified code paths and fixes
- api/chat.php: The former async console POST acknowledged pending work without recording a queued agent run. It now persists the existing owner-scoped job before acknowledging. On a schema/write failure, it does not advertise a recoverable job and retains its existing detached background fallback.
- js/console-app.js: Previously, active-run recovery only started a status poll, even when a server run was merely queued and never started. The client now claims a queued run once using its original turn/character. Running base jobs are observed via poll; regeneration requests use their original request key. History recovery requires the current view epoch. No duplicate messages or model requests are intentionally created.
- js/console-app.js: Work events are stored per session even while another chat is visible; the DOM is updated only for the active session.
- js/console-app.js: Standard final replies are rendered offscreen and replace just the typing row. Existing uploaded images, old avatars and open work cards are preserved. Variant actions and rendering exceptions retain a full-render fallback. Images decode asynchronously.
- api/console_agent_loop.php: The restricted and permission-scoped read-only parser now matches "Ich lese dir jetzt script.js durch". Edit and execution intents are not inferred.
