ZIEL
Eigenstaendiger, isolierter und sicherer CoreAI-Deinstaller fuer
offizielle Docker-Installationen /opt/ember-coreui. Zugang auch dann,
wenn der Update- oder Webzugang des CoreAI nicht mehr funktioniert.

CLI
- scripts/uninstall.sh --dry-run (nur Vorschau)
- scripts/uninstall.sh --execute (ausdrueckliche interaktive
  Bestaetigung COREAI ENTFERNEN, komplette Installation als Archiv)
- scripts/uninstall.sh --purge-data (nur SSH, separate staerkere
  Texteingabe, geloeschte Daten sind endgueltig weg)
- Einzelausfuehrung ueber temporaer heruntergeladenes GitHub-Skript
  direkt aus README dokumentiert.

ADMIN CORE > BETRIEB
- Owner-only Karte, initial verborgen; GET uninstall_status
  zeigt Hostdienst und CSRF nur beim Inhaber.
- POST uninstall_request erfordert Owner-Recht, CSRF, aktuelles
  Passwort und korrekte Zeichenfolge COREAI ENTFERNEN.
- Feste Anfrage ohne Shellkommando und ohne frei waehlbare Pfade.
  Im Web nur Archiv-Deinstallation, niemals --purge-data.
- Der Host bekommt die Anfrage per atomic rename, schliesst
  doppelte Anfragen aus und fuehrt sie als root per systemd aus.
- Dienst wird von scripts/install.sh eingerichtet und besitzt
  eigenen *.path + *.service; bei fehlendem systemd bleibt CLI.

SICHERHEIT
- Fester Standardpfad und Datei-Marker, keine Symlink-/Mount-Pfade.
- Gemeinsames Update-Lock und Sperre bei anstehendem Update.
- Nur docker compose --project-name ember-coreui down (keine Volumes).
- Nur explizite CoreAI-systemd-Units entfernen, keine globalen Dienste.
- Ollama-Modellbestande, Docker, Apache/Nginx, Swap und fremde Apps
  werden nicht angefasst. Betreiber-Konfigurationen fuer Reverse
  Proxies muessen separat entfernt werden.
- Browser-Anfrage wird vor dem Archivieren verbraucht, damit eine
  Wiederherstellung keine neue Deinstallation ausloest.
