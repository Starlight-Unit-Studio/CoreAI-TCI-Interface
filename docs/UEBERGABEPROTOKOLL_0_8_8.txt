Operator intent
A normal main chat must be a complete work chat. Projects are optional organizational and memory-isolation features. Reuse the existing Project Files UI instead of creating another editor.

Source findings
- Existing editor, preview, terminal, development server and version history all live inside the one #projectFilesPanel owned by js/coreui-project-files.js.
- Existing pfile backend authorized files using only project_id; ordinary chat sessions lacked a storage root.
- A saved historical plan and the native/Python full-site builder could override newer requests such as adding blog.html.
- The chat input placeholder can be reset by profile refresh and is NOT an authorization signal.

Implementation
- Migration 056: hidden workspace_session_id with unique per-chat backing project and ON DELETE CASCADE. CoreAI project list excludes internal workspaces.
- Normal session creation transactionally provisions its private workspace; older existing chats gain it lazily. Workspace APIs enforce account ownership, active/unlocked session and CSRF.
- Same existing pfile/project-run/process/VCS APIs; no duplicate runtime and no new arbitrary shell authority.
- Existing project chats use their named Project workspace; ordinary chats use a hidden session workspace without isolation of global memory.
- A mobile chat tab and desktop rail action open a modal. The real Project Files panel moves into it and returns intact; editor state, controls, previews and listeners are reused.
- Populated source workspaces avoid stale whole-site rebuild prompts. Native tool block correction remains strict and type-sensitive.
- Preflight, regression tests, source fingerprints, README, roadmap and version files synchronized.

Limitations
- Previously generated downloads do not automatically migrate when the modal opens.
- Moving a file-backed ordinary chat into a named Project needs an explicit conflict-aware file import.
- Text sources are in the file workspace; other binary artifacts stay in the download system.
