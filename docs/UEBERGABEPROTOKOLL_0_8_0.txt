Root causes
1. api/console_stream.php: SSE fast path previously recognized ordinary web,
   browse, Python, archive and image markers, but not project file/process/
   version markers, so those tool calls could become ordinary final prose.
2. Some small Cores announce a file read without emitting a DATEI marker.
   The synchronized agent parser correctly requires an explicit tool marker,
   and therefore saw only a final answer.

Fix
- api/console_stream.php: permission-scoped project marker detection, before
  final reply save and after truncated-stream continuation. It hands requests
  to the existing synchronous guarded dispatch path.
- api/console_agent_loop.php: tightly constrained read-intent recovery only
  for short, unambiguous, first-person file-read intentions with a safe,
  relative project path. Access is restricted by pfile_read availability.
  The original coreui_pfiles_path and account/project owner guards remain.
  No commands, edits or browsing may be inferred from prose. The same step
  recovery happens after later model calls inside the agent loop.
- api/chat.php: first-step recovery before its guarded project agent loop.
- scripts/agent-loop-selftest.php: explicit positive/negative cases and
  scripted two-file loop proving follow-up tool execution and result.
- scripts/image-gen-selftest.php: maintains the image stream dispatch contract,
  adapting its exact source check to the additional project marker guard.
- Existing Preflight entrypoints already run both tests; neither was bypassed.
- 0.8.0 release, README, branded version, changelog and numeric gate key.
